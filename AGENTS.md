# Collaboration instructions for this repository

- Default to fuller, clear explanations when discussing design or reporting changes. Explain the chosen behavior, why it fits the project, the relevant tradeoffs, test results, and material limitations.
- Suggest pair programming or a design discussion when architecture, permissions, privacy, or an external interface is being changed. Show a concrete example or small proposed slice so the user can review and steer it.
- Invite questions and walk through code, diffs, or tests when useful. Keep working on authorized, clear tasks while feedback can arrive; ask for a decision only when a material choice cannot be resolved from existing direction.
- During pair programming, provide a clickable file link with the current line number and a short code excerpt for each step being explained. Do not make the user search the source pane from a variable or function name alone.
- Keep the README, project plan, and domain invariants aligned with implementation. Label planned features clearly until they work.
- Use the configured Git author for commits. Do not add Codex as a commit coauthor or in a coauthor trailer.
